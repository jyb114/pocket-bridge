# DSH mobile acceptance - preview.10

Updated 2026-10-06 (UTC). New installers are DSH-only. This record separates actual runtime operations, controlled tests and outstanding checks. It does not certify every feature, version or physical device.

## Preview.10 actual npm operation

Four published npm versions were run locally in separate D-drive environments: 0.1.0-rc.8, 0.1.1-rc.2, 0.1.7-rc.2 and 0.2.0-rc.2. Actual pointer/keyboard operations covered different subsets; see the [current compatibility table](DSH-COMPATIBILITY.md). Successful modern replies, question answers and approval allow/reject results came from the real DSH/model processes. The old versions' model and tool selections were confirmed through independent readback; their missing valid API-key errors remain credential failures.

The measured mobile layouts were 390-by-844 with no horizontal overflow. Earlier operations in tabs that retained a desktop-sized viewport are not relabelled as mobile-sized acceptance. Desktop-browser viewport emulation does not operate a physical iPhone or Android keyboard/network. Actual Save links in the current in-app browser did not produce a confirmed completed download; historical downloads and controlled download fixtures remain separate evidence.

The new durable replay, WebSocket, screenshot-schema, private-HTTPS admission, capability panel and legacy refresh regressions use owned isolated fixtures. They do not establish real Tailscale enrollment, a production replay attack, physical-phone recovery or all-feature compatibility. Publication requires fresh whole-suite CI and compiled installer/payload/privacy gates for the final source.

## Isolated browser and protocol checks

The current real Chromium action fixture passed **192 checks**, retaining command/session fencing, permission readback, uncertain queue/goal edits, image Retry, keyed rows, streaming coalescing and byte-exact completed downloads. It also exercises actual original File uploads, temporary-preview eviction and cancellation, lazy official image-ID reads, and persisted English/Spanish reload and remount against the default Chinese HTML. The language regression reproduced the original failure before the fix and checks 12 static controls per locale. The existing full UI, adapter and language suites passed at author freeze. These use controlled upstream data and do not certify the corresponding public or physical-phone operation.

An earlier candidate completed **89 isolated CI entries**. That result predates the latest language and runtime corrections and is not final acceptance of their source tree. Shared security fixtures retain proof/auth/key-loss negatives; remote raw/classic HTTP and unknown WebSocket routes are refused before dispatch. Final CI, compiled installer, payload identity and privacy results must refer to the final frozen candidate.

## Compatibility and parity

The [compatibility matrix](DSH-COMPATIBILITY.md) records four actual historical npm web-version experiments, their prepared dependency graph, the successful flows and the credential/device limits. They have not all been repeated against this candidate. Old desktop wrappers and arbitrary plugin combinations are not certified by those tests.

This phone interface exposes capabilities supplied by the connected runtime. Complete desktop-plugin parity is not claimed. Tool activity and reasoning depend on exposed runtime data. Generic pathless uploads have a temporary preview only when this page retained the verified original File; a reload or cache eviction removes it. Official image-reference retrieval is a separate, session-authorized operation, accepted for one actual historical tool-image preview. Arbitrary text-file upload remains unsupported on the legacy protocol. An unsupported control must be unavailable or explain its limit; its appearance is not a passed action.
